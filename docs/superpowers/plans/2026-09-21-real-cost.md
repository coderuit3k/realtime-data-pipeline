# Real month-to-date cost Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the static `COST_ESTIMATE_USD = 1.02` figure shown on Dashboard and Ops with a real, live AWS Cost Explorer query returning genuine month-to-date spend, served from its own 24h-cached route.

**Architecture:** New `web/lib/costExplorer.ts` calls `GetCostAndUsageCommand` via a new `getCostExplorerClient()` (hardcoded `us-east-1`, Cost Explorer's fixed real endpoint). A new `GET /api/cost` route wraps it with a 24h `Cache-Control`, decoupled from Dashboard/Ops's existing ~60s-fresh routes. `costEstimateUsd` is removed from `DashboardResponse`/`OpsResponse`; both pages gain an independent, non-blocking `fetch("/api/cost")` on mount, matching Weather's established secondary-fetch pattern. Landing is untouched — it keeps its static `MONTHLY_COST_USD`.

**Tech Stack:** Next.js 15 App Router, TypeScript, Vitest, `@aws-sdk/client-cost-explorer` (new dependency).

**Spec:** `docs/superpowers/specs/2026-09-21-real-cost-design.md`

## Global Constraints

- Landing (`/`) gets no live fetch — it keeps showing the existing static `COST_ESTIMATE_USD` via `landingMeta.ts`'s `MONTHLY_COST_USD`, unchanged.
- No new infrastructure (Lambda, cron, S3/DynamoDB cache) — Vercel's CDN `Cache-Control: s-maxage` is the only caching mechanism.
- No cost breakdown by service/dimension (`GroupBy`) — just the one real month-to-date total.
- `getCostExplorerClient()` is the one client getter in `web/lib/aws.ts` that does NOT read `AWS_REGION` — it is hardcoded to `"us-east-1"`, Cost Explorer's real fixed endpoint region, with an inline comment explaining why.
- `TimePeriod.End` is exclusive (real AWS SDK doc comment) — to include today's data, `End` must be tomorrow's date (UTC), not today's.
- Verified real SDK field names (from `@aws-sdk/client-cost-explorer`'s actual `.d.ts`, checked during brainstorming): `GetCostAndUsageRequest { TimePeriod: DateInterval {Start, End}, Granularity, Metrics: string[] }`, `GetCostAndUsageResponse { ResultsByTime?: ResultByTime[] }`, `ResultByTime { Total?: Record<string, MetricValue> }`, `MetricValue { Amount?: string; Unit?: string }`.
- `/api/cost`'s `Cache-Control`: `public, s-maxage=86400, stale-while-revalidate=172800` (24h — matches Cost Explorer's own ~8h refresh cadence closely enough, keeps this route's real API cost to ~$0.01/day = ~$0.30/month).
- A failed `/api/cost` fetch must never block Dashboard/Ops's primary content — the cost KPI card shows its own independent loading/fallback state ("—") while the rest of the page renders normally.
- Error handling matches the established convention everywhere else: `console.error` + `{ error: "..." }` (Vietnamese, safe message) at 500, uncached.
- `getMonthToDateCostUsd` returns `0` (not a throw) when `ResultsByTime` is empty/missing — a brand-new month's first query could plausibly return an empty result set before any cost has accrued.
- `COST_ESTIMATE_USD` in `web/lib/opsMeta.ts` stays exactly as it is — Landing still imports it via `landingMeta.ts`'s `MONTHLY_COST_USD`. Only `COST_BREAKDOWN` gains one new entry.
- New IAM grant (`ce:GetCostAndUsage`, `Resource: "*"`) is added by the user running their own documented script — never by the assistant or CI.

- [ ] **Step 5: Write `web/lib/costExplorer.ts`**

```ts
import { GetCostAndUsageCommand, type CostExplorerClient } from "@aws-sdk/client-cost-explorer";

function monthToDateRange(now: Date): { Start: string; End: string } {
  const year = now.getUTCFullYear();
  const month = now.getUTCMonth();
  const day = now.getUTCDate();
  const fmt = (d: Date) => d.toISOString().slice(0, 10);
  return {
    Start: fmt(new Date(Date.UTC(year, month, 1))),
    // End is exclusive (real AWS SDK doc comment) -- tomorrow, UTC,
    // includes today's data.
    End: fmt(new Date(Date.UTC(year, month, day + 1))),
  };
}

// Real month-to-date spend via AWS Cost Explorer's GetCostAndUsage.
// UnblendedCost is the standard "what this actually costs" metric --
// this project has no reserved capacity, so it doesn't diverge from
// AmortizedCost in practice. Returns 0 (not a throw) when
// ResultsByTime is empty -- a brand-new month's first query can
// plausibly return no results yet.
export async function getMonthToDateCostUsd(client: CostExplorerClient, now: Date = new Date()): Promise<number> {
  const response = await client.send(
    new GetCostAndUsageCommand({
      TimePeriod: monthToDateRange(now),
      Granularity: "MONTHLY",
      Metrics: ["UnblendedCost"],
    })
  );
  const amount = response.ResultsByTime?.[0]?.Total?.UnblendedCost?.Amount;
  return amount ? Number(amount) : 0;
}
```

```ts
import { NextResponse } from "next/server";
import { getCostExplorerClient } from "@/lib/aws";
import { getMonthToDateCostUsd } from "@/lib/costExplorer";
import type { CostResponse } from "@/lib/types";

export const maxDuration = 60;

export async function GET() {
  try {
    const monthToDateCostUsd = await getMonthToDateCostUsd(getCostExplorerClient());

    const response: CostResponse = { monthToDateCostUsd };

    // 24h cache, decoupled from Dashboard/Ops's own ~60s-fresh data --
    // Cost Explorer's underlying data only refreshes ~every 8h anyway,
    // and each real query costs $0.01.
    return NextResponse.json(response, {
      headers: { "Cache-Control": "public, s-maxage=86400, stale-while-revalidate=172800" },
    });
  } catch (error) {
    console.error("Cost API failed", error);
    return NextResponse.json({ error: "Không tải được chi phí, thử lại sau." }, { status: 500 });
  }
}
```
